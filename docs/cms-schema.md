# CMS schema (PostgreSQL)

Status: current as of Phase N-0

"CMS" here means the project's own admin + API. No third-party CMS is used ([`architecture.md`](architecture.md) §1).

This document is the table-by-table reference of the schema as implemented. Sources:
- `apps/api/src/db/schema.ts` (Drizzle);
- `apps/api/drizzle/0000`–`0010` (SQL migrations);
- `apps/api/db/provision.sql` (roles).

Design rules, import/export and decisions DB-1…DB-12: [`admin-database.md`](admin-database.md). The content meaning of the fields: [`content-model.md`](content-model.md).

**PostgreSQL 17, 46 tables, 1 sequence (`lead_number_seq`), 18 enums.** No extensions are created by the migrations.

---

## 1. Conventions

| Convention | Detail |
|---|---|
| Primary keys | UUIDv7 generated by the application (`uuid` package). Exceptions: `audit_events`, `content_revisions` and `release_events` use `bigint` identity; `locales.code` is text; join and translation tables use composite PKs |
| Stable key | `key text UNIQUE NOT NULL` on content tables, e.g. `project-solbar-israel`. Never changes |
| Entity / translation split | `<entity>` holds language-independent data. `<entity>_translations` has PK `(entity_id, locale)` and one row per locale |
| Publishable entity columns (`entity()`) | `id`, `key`, `status content_status DEFAULT 'draft'`, `position`, `source_locale → locales DEFAULT 'en'`, `version` (optimistic lock), `source_revision` (0004), `published_at`, `archived_at`, `schema_version`, `created_at/updated_at`, `created_by/updated_by → users RESTRICT` |
| Translation row columns (`translation()`) | `locale → locales`, `tr_status translation_state` (NULL for the source language), `approved_source_hash`, `approved_at date`, `schema_version`, audit columns |
| Translation review columns (0004) | `version`, `approved_source_revision`, `approved_by → users`, `edited_source_revision`. Present on the 7 admin-managed translation tables |
| SEO text columns | `seo_meta_title`, `seo_meta_description` (NULL = frontend default) on project, technology, product and page translations |
| FK policy | Content → content and content → media: `ON DELETE RESTRICT`. Translation and child rows: `CASCADE` |
| JSONB | Only for ordered lists inside a translation and for code-defined maps. Each has a Zod schema in `packages/core/src/content/jsonb.ts` (`TextListV1`, `LabelValueListV1`, `TitleDescriptionListV1`, `PatentInfoV1`, `PageCopyV1`, `PageBodyV1`, `ListItemTextsV1`). Columns whose key order matters use `json` (`page_list_items.structure`, `content_revisions.data`, `content_snapshots.store`) |

## 4. Migrations

All migrations are in `apps/api/drizzle/`, journal `meta/_journal.json`. Apply with `npm run db:migrate` (uses `MIGRATION_DATABASE_URL` with the `soltex_migrate` role). Everything from 0004 on is additive.

| # | File | One line |
|---|---|---|
| 0000 | `0000_content_schema.sql` | 6 content enums and 29 content tables (media, technologies, projects, products, EPCM stages, patents, videos, pages + slots/lists, settings, metrics, offices, redirects, locales) |
| 0001 | `0001_locales_reference_data.sql` | Inserts the 6 locales; revokes INSERT/UPDATE/DELETE on `locales` from `soltex_app` |
| 0002 | `0002_auth_users_sessions_audit.sql` | Users, sessions, known devices, WebAuthn credentials and challenges, TOTP, recovery codes, password resets, `audit_events`; `created_by`/`updated_by` FKs to `users` |
| 0003 | `0003_audit_append_only.sql` | Revokes UPDATE/DELETE/TRUNCATE on `audit_events` from the app role; triggers refuse UPDATE/DELETE/TRUNCATE for every role |
| 0004 | `0004_translation_review.sql` | `source_revision` on 7 entities; `version`, `approved_source_revision`, `approved_by`, `edited_source_revision` on their translations |
| 0005 | `0005_publishing.sql` | `content_revisions`, `content_snapshots`, `releases`, `release_events`, `preview_grants`; 3 enums; append-only and immutable-column triggers |
| 0006 | `0006_redirects_version.sql` | `redirects.version` (optimistic lock) |
| 0007 | `0007_media_library.sql` | `media_source` enum; library columns on `media`; `sha256` index; `media_upload_path` CHECK |
| 0008 | `0008_media_variants.sql` | `media.variants` jsonb |

| 0010 | `0010_temporary_password.sql` | `users.password_temporary` |

After migrating, `db:migrate` and `db:import` also link existing approvals to revisions (`content/reconcile.ts`) and write baseline revisions ([`admin-database.md`](admin-database.md) §7).

## 5. Roles and grants

`apps/api/db/provision.sql` is run once per environment as superuser. Passwords are passed as psql variables.

| Role | Rights | Used by |
|---|---|---|
| `soltex_migrate` | Owns the database and `public` schema | `npm run db:migrate` only |
| `soltex_app` | Default privileges: `SELECT, INSERT, UPDATE, DELETE` on tables and `USAGE, SELECT` on sequences created by `soltex_migrate`. No DDL, no TRUNCATE. `NOSUPERUSER NOCREATEDB NOCREATEROLE NOREPLICATION NOBYPASSRLS` | API, worker, preview server, `db:import`/`db:export` |
| `soltex_backup` | `pg_read_all_data` | Backups (Phase N) |

`PUBLIC` loses all rights on the database and schema.

**Per-table restrictions on `soltex_app` (migrations):**

| Table(s) | Revoked | Trigger | Effect |
|---|---|---|---|
| `locales` | INSERT, UPDATE, DELETE | — | Read-only |
| `audit_events` | UPDATE, DELETE, TRUNCATE, REFERENCES, TRIGGER | `audit_events_no_update_delete` (row), `audit_events_no_truncate` (statement) | Append-only for **every** role, owner included |
| `content_revisions`, `content_snapshots`, `release_events` | UPDATE, DELETE, TRUNCATE, REFERENCES, TRIGGER | `*_append_only` (BEFORE UPDATE OR DELETE) | Append-only. The owner can still TRUNCATE (test resets) |
| `releases`, `preview_grants` | DELETE, TRUNCATE, REFERENCES, TRIGGER | `releases_immutable` on `releases` | No deletes. On `releases`, identity, snapshot and (once set) artifact columns are immutable |

`apps/api/src/db/db.test.ts` tests these rules.

## 6. Retention, anonymization and cleanup

| Data | Job | Rule |
|---|---|---|
| Leads | Worker, hourly: `anonymizeDue()` in `apps/api/src/leads/service.ts` | Leads deleted more than 30 days ago (`LEAD_DELETE_GRACE_DAYS`), or created more than `LEAD_RETENTION_MONTHS` ago (default 24, allowed 1–120), are anonymized. The job nulls `name`, `company`, the encrypted contact fields, blind indexes, `ip_hash` and `attribution`, and nulls `lead_events.note_enc`. It then writes an `anonymized` event and one `lead.anonymize` audit entry. Up to 500 rows per run. Date, form, locale, page, topic and status remain |
| Audit log | none | Kept forever. Pruning needs a separate reviewed migration that works around the trigger (comment in 0003) |
| Revisions, snapshots, releases, release artifacts | none | Never deleted. Pruning is a later decision ([`admin-publishing.md`](admin-publishing.md)) |
| Expired service rows | Worker, hourly: `cleanupExpired()` in `apps/api/src/system/cleanup.ts` (Phase N-0) | Deletes `webauthn_challenges` expired > 1 day, `password_resets` expired > 30 days, expired `known_devices`, `sessions` ended (expired or revoked) > 30 days unless referenced by `preview_grants`, `outbox` rows sent > 30 days. One `system.cleanup` audit entry (`count`, `kind`) when anything was deleted |
| Preview grants | none | Append-only; kept as a record ([`admin-database.md`](admin-database.md) §8) |
| Media files | none | Files are immutable. Unreferenced files are meant for a later garbage collection that respects backup retention (`apps/api/src/media/storage.ts`) |
